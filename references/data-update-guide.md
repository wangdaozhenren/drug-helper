# 年度数据更新流程（医保目录/药典新版后重跑）

> 本技能三源数据（NMPA 批准信息 / 国家医保药品目录 / 中国药典）随官方版本周期更新。
> 当前数据版本：2026.09.21-v1（医保目录 2025 版、药典 2025 年版）。
> 当医保目录新版、药典新版或 NMPA 批准信息批量更新发布后，按本流程重跑数据。
> 最后核验：2026-09。

## 一、何时触发更新

- 国家医保药品目录发布新版（通常按年度调整）；
- 《中国药典》发布新版（通常五年一版，期间有增补）；
- NMPA 批准信息出现批量结构性调整；
- 合规要求或平台审核指出数据时效问题。

## 二、更新步骤（在 fc-backend 目录执行）

1. **获取新版源数据**：从官方公开渠道下载新版医保目录（PDF）、药典品种正文、NMPA 批准信息；爬取遵守限速（3~5 秒/请求 + 随机抖动，单源串行，遇 403/429 即停）。
2. **重跑 `prepare_data.py`**：在 `fc-backend/` 下执行数据准备脚本，生成新的高频子集（`data/high_freq_drugs.json`）与全量服务端索引（`data/drug_server_index.json`），并上传 OSS。
3. **更新技能包精简索引**：重新生成 `drug-guide-skill/data/drug_archive_index.json` 精简检索索引。
4. **复核 OTC 白名单**：核对 `drug-guide-skill/data/otc_whitelist.json` 是否需要随新版调整（处方药拦截门控依据，改动须单独评审，不在本次普通更新内自动变更）。
5. **更新版本号与核验日期**：在 SKILL.md、compliance_notes.md、输出免责声明模板中同步"数据版本号 + 核验日期"。
6. **回归测试**：跑 `tests/test_skill.py` 与 FC 后端接口测试（verify_live 系列），确认 OTC 命中返回完整档案、处方药仍只返回拦截话术。
7. **重新打包发布**：build_pkg / package_skillhub 流程不变。

## 三、边界与红线

- **处方药拦截逻辑（otc_gate.py / 拦截话术 / v2.1.0 免费模式）不在本更新流程内改动**；如需调整须走单独评审。
- 数据更新只换数据，不改输出模板与拦截规则。
- 每次更新留版本号与核验日期，便于追溯。
